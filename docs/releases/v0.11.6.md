MTUI v0.11.6 improves recovery from missing synced lyrics and reduces unnecessary foreground rendering.

## Changes

- Lyrics that initially arrive as plain text, or fail to load, retry twice after 2 and 8 seconds while the Lyrics tab is selected. Existing words remain visible and upgrade to synced lyrics when timestamps arrive, without restarting playback. Late failures cannot replace an already synced result.
- Successful synced lyrics for up to 16 recent tracks are cached in memory for the current session, with a 32 KiB text allowance per entry. Plain lyrics and failures remain retryable. Replaying a cached track reuses its successful timings.
- LRCLIB search examines more candidates and selects matching artist, title, recording duration, and album rather than the first timed result. Synced words stay together with their timestamps and provider credit. Provider failures are recorded in diagnostics, and plain results are labeled **Unsynced lyrics**.
- YouTube lyrics parsing skips empty timing models when a later model has valid cues. Timed lines are sorted and the current lyric is found with binary search.
- Foreground worker polling is separate from rendering. Input, source responses, playback state changes, and lyric cues trigger a frame; otherwise the display refreshes once per second. Overflowing titles retain their 200 ms animation cadence. Artwork no longer rebuilds on every unchanged poll.
- Windows checks an empty input pipe every 8 ms instead of 2 ms. The startup handshake keeps its separate fast interval, and audio scheduling is unchanged.

## Performance evidence

A local Windows release benchmark of 1,000 simulated foreground polls reduced App/UI processing time by 81.8% for a playing queue, 80.3% for a paused queue, and 75.0% for synced lyrics. Final visible buffers matched in each case. These are headless processing measurements, not whole-app CPU or GPU reductions; they exclude real audio decoding, network, helper processes, and terminal rendering. Startup and track-loading latency were not measured. See the [method and results](https://github.com/lightzgls/mtui/blob/v0.11.6/docs/performance.md).

Validation before publishing includes 610 isolated Windows tests and strict Clippy, plus a separately selected read-only LRCLIB check for **drop dead — starfall** that returned 48 timed lines and verified replay from cache. Published packages also pass the release workflow's Windows runtime-import checks and Linux installation/update smoke tests. Synced lyrics still depend on timestamps being available for the recording and a working provider connection.

## Install or Upgrade

**Windows:** use **Settings → Updates**, or download `MTUI-0.11.6-Setup-x64.exe`. A single portable executable is also available. Updates preserve account data and preferences.

**Linux:** run as your normal user:

```sh
curl -fsSL https://github.com/lightzgls/mtui/releases/latest/download/install.sh | bash
```

Writable per-user Linux installations can also use **Settings → Updates**. System-managed Debian/Ubuntu installations should install the new `.deb`, version `0.11.6-1`. Prebuilt Linux packages require x86-64, glibc 2.34+, and compatible audio, TLS, D-Bus, and WebKitGTK runtimes.
